# Git 提交信息规范

## 提交格式

```
<类型>(<范围>): <简短描述>

<详细说明>
```

## 类型说明

| 类型 | 说明 |
|------|------|
| `feat` | 新增功能或特性 |
| `fix` | 修复 bug |
| `docs` | 文档更新 |
| `style` | 代码格式调整（不影响功能） |
| `refactor` | 代码重构 |
| `test` | 测试相关 |
| `chore` | 构建或工具配置更新 |
| `perf` | 性能优化 |
| `revert` | 回滚提交 |

## 示例

```
feat(音频): 添加离线语音唤醒功能

- 集成 ESP-SR 唤醒词模型
- 支持"你好小智"唤醒词
- 优化唤醒灵敏度
```

```
fix(构建): 修复 esptool merge-bin 命令错误

esptool v4.x 使用下划线格式的命令参数 merge_bin，而非连字符格式
```

```
docs(文档): 更新固件烧录教程

添加一键刷入和分区刷入两种方式的详细说明
```

## 规范要求

1. **简短描述**：不超过 50 个字符，使用中文
2. **详细说明**：如需详细说明，空一行后编写
3. **类型选择**：根据提交内容选择合适的类型
4. **范围指定**：可选，用于标识修改的模块或功能
5. **时态**：使用现在时（如 "添加" 而非 "添加了"）
